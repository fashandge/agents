# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, OpenClaw, Hermes, and similar tools) when working with code in this repository.

## Project

`agents` is a small Python library of reusable utilities for driving AI coding-agent CLIs (Codex, Claude Code, Gemini/`agy`) and for calling chat-completion APIs (OpenRouter and DeepSeek). It is consumed by other local projects as a package — modules are imported as `from agents import <module>` (resolved via the `~/projects` editable install, per the global CLAUDE.md).

## Common commands

- Run tests: `/opt/homebrew/Caskroom/miniconda/base/envs/ml/bin/python -m pytest tests/`
- Run a single test: `... -m pytest tests/test_openrouter.py::test_openrouter_client_sends_chat_completion_request`
- Source Codex bin/node discovery (finds newest NVM node with `codex` installed and exports `CODEX_BIN` / `CODEX_NODE_BIN`): `source scripts/codex-env.sh`
- Run an agent from the shell: `python agents_cli.py [-a claude|codex|gemini] [-m MODEL] "prompt"` — prompt can also be piped via stdin or supplied as a heredoc. Use `--fallback claude,codex,gemini` to walk a fallback chain.
- Invoke native code review: add `--codex-review` to pass the prompt through headless `codex exec review`, or `--claude-review-command code-review|review` (and an optional PR `--claude-review-target` for review).
- Long runs (> ~6 min) launched from a cmux-hosted Claude Code session: add `--detach OUTPUT_BASE` — runs in its own session (immune to the cmux idle reaper), answer in `OUTPUT_BASE.out`, `.exitcode` written last (poll for it). Short runs don't need it.
- Spawn a worker in a new tab with no protocol, monitoring, or bookkeeping (the default way to delegate): `scripts/spawn_worker.sh --help`.
- Create/inspect a durable handoff run: `/opt/homebrew/Caskroom/miniconda/base/envs/ml/bin/python -m agents.orchestration.handoffctl --help`; launch one through local cmux/tmux or remote SSH+tmux with `scripts/handoff_agent.sh --help`.
- Update a host checkout and migrate its handoff state together: `scripts/update_agents.sh`; use `--dry-run` to inspect migration work without pulling or writing state.

## Architecture (details: docs/architecture.md)

- **`env.build_env()`** — sources `~/.zshenv` + `~/.config/secrets.env` into an env dict for `subprocess.run(env=...)`; the single entry point for PATH/API keys under launchd/cron.
- **`coding_agents_cli`** — unified blocking interface for the three agent CLIs: `AgentConfig` dataclass (all options, including native-review routing, are agent-name-prefixed), `run_with_config()`, `run_with_config_and_fallback()` (Codex → Claude → Gemini).
- **`coding_agents_streaming`** / **`claude_pty_wrapper_streaming`** — same agents, yielding `AgentStreamEvent`s as the process runs.
- **`openrouter`** / **`deepseek`** — small, self-contained, stdlib-only chat-completion clients (deliberately share no code).
- **`openclaw`** — messaging wrapper over the `openclaw` CLI (`send_message` / `send_discord`); no network call or token in this repo.
- **`orchestration.handoff` / `orchestration.handoffctl` / `orchestration.handoff_registry` / `orchestration.handoff_watcher`** — standard-library local-v1 durable handoff protocol plus private run and orchestrator-session state. Current runs park at `paused` after an accepted review, derive fatality from the live worker epoch's outbox, and use registry `finished_at` rather than worker stop states; legacy lifecycle vocabulary remains read-tolerant. Generic `watch` remains a JSONL observer; detached orchestrator mode dynamically discovers only owned runs, persists credential-free notification cursors, coalesces opaque doorbells without consuming worker events, and binds its lifetime to the exact orchestrator PID plus process-start identity. cmux orchestrator doorbells pair an echo-confirmed typed prompt into the orchestrator surface — the only channel that pushes a hosted agent to act; a zero-exit `cmux send` alone proves nothing — with a visible `cmux notify` alert for the human; the watcher records the accepted channel(s) in `last_doorbell_method` (e.g. `cmux_input+cmux_notify`), never confirmed user visibility. The typed channel is gated on the orchestrator's composer so a doorbell never lands mid-draft: an empty composer sends now, a draft on an unfocused surface is forced with a self-describing draft-preservation prefix (`cmux_input_forced`), and a draft on the focused surface defers (`deferred_input`, retried next poll) until it stops changing. The cmux server rejects socket calls from launchd-orphaned clients under the default `socketControlMode: cmuxOnly`, so cmux orchestrators default to a **surface-hosted** watcher (`orchestrator start --mode auto|detached|surface`): a dedicated in-tree cmux terminal surface (named `watcher: <workspace>`, parked in a bottom `handoff-watchers` workspace) runs the watch loop in its foreground, native `cmux notify` doorbells work, and the tab is the watcher's visible log — closing it kills the watcher and `orchestrator start` relaunches it. tmux orchestrators keep the detached daemon and typed doorbells; an explicitly detached cmux watcher degrades to a recorded `macos_notification`. Orchestrator `send` rings the worker's terminal doorbell by default for registered local runs (best-effort, reported as `doorbell_sent`/`doorbell_error`; `--no-doorbell` opts out), while `dispatch` remains the one-shot steer for callers holding no active lease.
- **`orchestration.spawn_worker` / `scripts/spawn_worker.sh`** — lightweight counterpart to the launcher below and the default delegation path: opens a tab (herdr, else cmux, else tmux; remote is herdr-only, into `REMOTE_WORKERS`), starts the agent on a task prompt, prints one JSON line, and returns. It reuses the launcher's adapters, `AGENT_DEFAULTS`, argv construction, folder-trust rescue, and SSH transport, and creates no run directory, credentials, lease, registry entry, or watcher. Its wrapper is a separate entry point that strips `HANDOFF_RUN_DIR`/`HANDOFF_WORKER_TOKEN_FILE` rather than merely not setting them (`build_env()` copies `os.environ`, so a spawn from inside a handoff worker would otherwise inherit that run's pointers) — a lightweight worker must not believe it is in a handoff run. The `spawn-worker` skill owns the prompt contract: a plain task, no role, no protocol, no awareness of an orchestrator.
- **`orchestration.handoff_launcher` / `scripts/handoff_agent.sh`** — safe local cmux/tmux and remote SSH+tmux launcher for Claude Code (`opus/high`), Codex (`gpt-5.6-terra/xhigh`), Kimi Code (`kimi-code/k3`/`max`), and pi (`deepseek/deepseek-v4-flash`/`max`), with model/effort overrides; remote requests carry kickoff bytes as JSON over SSH stdin and keep the authoritative run on the worker host. Launch-only returns without a readiness wait, except Codex (local and remote) makes one bounded startup check to rescue its exact folder-trust dialog — reporting `folder_trust_rescued`/`startup_unconfirmed`, with the local check matching the launch `cwd` by prefix since a narrow surface truncates the path; managed monitoring is opt-in. Companion helper scripts (details: docs/architecture.md): `scripts/handoff_orchestrator_ensure.sh` (idempotent watcher bootstrap), `scripts/handoff_doorbell.sh` (manual doorbell with submit discipline), `scripts/cmux_close_surface_safe.sh` (guarded single-surface close), `scripts/tmux_run_logged.sh` (logged batch session with live pane), `scripts/update_agents.sh` (pull + migrate together, since the checkout is the runtime), `scripts/fleet_status.sh` (drift across every checkout on every host — run before delegating remotely and after integrating).
- `agents_cli.py` — thin argparse shell entry point over `coding_agents_cli`.

## Rules that change what you do

- Blocking Claude runs default to **direct `claude -p`** (`claude_use_pty_wrapper=False`): the pty-wrapper leaks/hangs on plugin MCP servers in headless runs (wrapper teardown bug — see docs/architecture.md). Keep `-p` the default for unattended callers; `claude_disable_mcp=True` / `--no-mcp` suppresses MCP entirely.
- Do **not** switch `claude_pty_wrapper_streaming` to `claude -p` — the wrapper path is intentional there.
- Gemini dispatches to the `agy` CLI (not `gemini`), prompt via stdin `--print -` (avoids `ARG_MAX`, no `shell=True`).
- New runners or wrappers must call `agents.env.build_env()` for their subprocess env — never construct one ad hoc — so cron/LaunchAgent execution keeps working.
- Add new agent options to `AgentConfig` with the agent-name prefix and resolve defaults in `__post_init__`; do not introduce parallel kwargs on `run_with_config`.
- Free-model list lives in `data/openrouter_free_models.txt` (one model id per line); `openrouter.py` reads it relative to its own file.
